# 0.5.0 工程门限评估

评估日期：2026-09-09。范围：skill 路由、G0–G8/M0–M4、后端接入门、
证据解析器、README 与软件发布检查。基于当前源码和维护约束；没有执行新的
COMSOL/MATLAB/仪器实验，也不声称强模型使用效率已有定量基准证明。

## 判断与处理

门限仍有保留意义，但应验证一个具体结论，而不是成为所有工作的统一前置流程。
强模型更适合自行选择诊断路径，仍然无法凭推理补齐未测量的相位、通量或收敛数据。

| 现有要求 | 判断 | 0.5.0 处理 |
|---|---|---|
| G0 契约 | 正式验收需要，探索阶段过早冻结会阻碍排错 | 只冻结待验收的声明；允许明确记录的临时假设 |
| G1 端口/直波导 | 能发现归一化、激励、基底及边界错误，应保留 | 正式全波验收和大规模算例前保留；已授权的小诊断不以通过 G1 为通用前提 |
| G2 完整复数 S | 对可复用散射模型必要，对几何、热场或单个本征模不适配 | 明确 G2 的模型类型与有效范围，不强行套到所有“组件”上 |
| G3/G4 电路契约和行为 | 可阻断连接、模式、参考面及相位错误，应保留 | 电路性能验收适用；不再是纯布局连接验收的前置条件 |
| G5 布局与连接 | 独立于光学性能也有价值 | 新增 `layout-connectivity`，只需 G0/G5；原 `layout-tapeout` 保持原义 |
| G6 高保真晋级 | 声明跨模型精度时必要 | 作为适用的附加验收，不要求所有 2D EIM 结果先跑 3D |
| G7 优化/鲁棒性 | 对验收“改进”必要，对每次探索循环不必要 | 允许探索搜索；接受赢家时检查基线、噪声和声明范围，工艺角随鲁棒性声明启用 |
| G8 交付证据 | 正式工程证据包需要；普通回复和软件更新不需要 | 收窄触发范围，软件发布按维护测试处理 |
| M0–M4 测量链 | 原始数据、校准、关联、拟合应分清 | 新增 `measurement-capture`（M0/M1），不把采集完成当作校准通过 |
| SHA-256、路径/契约验证 | 防止证据漂移和错误输入，应保留 | 无放宽；历史状态与当前有效状态继续分开 |
| Phase A/B/C 后端接入 | 能防止“探测成功即已验证接入”的错误，应保留 | 不更改持久化接入记录或必需检查；单次受控实验不自动宣布整套接入已验证 |
| 发布与兼容性检查 | 防止包资源缺失和远端发布不一致，应保留 | 完整测试、wheel/sdist、隔离安装、PR CI 和远端提交签名验证 |

G/M 台账运行时是记录和评估服务，不是所有求解器命令的全局执行锁。
因此“减少门限”的核心是修正文档对模型决策的约束，而非添加一个跳过安全检查
的开关。项目自己的依赖顺序与授权约束继续有效，尤其不能由本次修改推导出
“项目明确禁止的 G1 前优化现在获准”。

## 数值与证据边界

- 不给所有器件设置统一功率残差、网格尺寸或固定细化次数；先定义所需精度与
  不确定度，再检查与结论有关的指标是否稳定。
- 无源性、互易性和幺正性各有物理前提；主动、非互易、有损或截断通道模型
  需要相应预算与说明，不能一律判为失败或通过。
- 所有必需的 `CHECK=PATH` 映射保留。一份简洁报告可以覆盖多个要求；
  条件不适用时在报告中说明原因与替代检查，不新增静默跳过单项要求的 API。
- 哈希只能验证所引用的文件仍然一致，不验证内容是否科学正确。
  缺少必要证据仍为 `blocked`，已完成且超差为 `fail`。

## 兼容性与验收

新增两个 profile 和说明字段；不改 GateRecord schema、既有 profile 的要求、
CLI 命令或已记录的后端接入结果。不把旧 ledger 自动迁移为更强结论。
profile 选择由项目契约/交接记录表达，运行时列出的是候选验收范围，并未持久化
一个“当前激活 profile”。

新增回归覆盖：无台账查询不写文件；窄范围通过不提升更广声明；证据变更后
窄范围也失效；G5 标记不适用不能使布局验收通过。原有路径、哈希、旧格式、
循环引用与 G/M 隔离测试继续执行。版本配套包括英文/中文 README、MCP 参考、
包版本、provider 示例和 CI 的工具数量/配方回执检查。

本地验证与远端 CI 的实际结果记录在对应 PR；该文档列出验收方法，不将尚未
执行的检查预先报告为通过。
